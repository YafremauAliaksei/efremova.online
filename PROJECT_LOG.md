### 🔀 2026-09-14 — цель проекта сузилась, и это главное изменение

До сих пор проект строился как «публичный сайт **плюс** кабинет клиента»
в одном приложении. Владелец пересмотрел порядок:

> «Сейчас отбрасываем ВООБЩЕ всё, что связано с личным кабинетом… я буду
> по старинке связываться по соцсетям с клиентами и вести свои дела без
> кабинета на сайте».

Новая цель: **сайт-визитка**, через который человек находит контакты психолога.
Кабинет уезжает на отдельный поддомен `cabinet.` и отдельный сервер в ЕС —
когда до него дойдут руки.

**Как теперь устроен сайт — [`docs/13-site-architecture.md`](docs/13-site-architecture.md).**
Это главный документ по архитектуре: страницы, блоки из базы, три языка,
кэш, картинки, отзывы. Там же очередь веток.

**Где мы сейчас:** фундамент готов и проверен запуском. Из репозитория вырезано
всё, чего в нём на самом деле не было (шаг 0.37). Дальше — контакты, шапка,
языки.

**Последний коммит:** `70b819e` — README и версии.

### Ничего не сломано

CI зелёный, открытых оповещений Dependabot нет, находок CodeQL нет.

⚠️ Но есть **известный разрыв**, найденный при сквозном чтении 2026-09-14:
middleware отправляет события о ловушках на `/api/internal/security/honeypot`
и `/api/internal/security/event` — **этих обработчиков в коде нет**. Ошибка
молча проглатывается, поэтому ничего не падает, но и ни одно попадание
в ловушку не записывается. Ловушки при этом работают: задержка и 404 честные.
Чинится следующей веткой `fix/security-events`.

### 🔑 Главное, что изменилось 2026-09-13 — работа идёт через pull request

Прямой push в `main` **запрещён на уровне GitHub**. Защита ветки включена
(шаг 0.27), обязательны три проверки: «Все ворота пройдены», DAST и Lighthouse,
плюс отсутствие находок CodeQL уровня High. Ветка обязана быть обновлена
от свежего `main`.

Процесс целиком, по командам: [`docs/11-git-workflow.md`](docs/11-git-workflow.md).
Агенту читать раздел 10 — там его обязанности.

### ⚠️ Три ошибки, которые стоит помнить

**1. Проверка может врать, и снаружи это не видно.** Итоговый гейт
«✅ Все ворота пройдены» полгода показывал зелёное, потому что в его `needs`
не было DAST и Lighthouse: он рапортовал об успехе за 4 секунды, не дождавшись
двух ворот. Именно этот гейт собирались сделать обязательным для защиты ветки —
защита оказалась бы декорацией.

**2. Проверять надо тот артефакт, который везём.** `npm start` вызывал
`next start`, несовместимый с `output: standalone`. Lighthouse и ZAP проверяли
сервер, которого нет ни в образе, ни в проде. Добавление иконки сайта не чинило
падение Lighthouse, потому что тот сервер её всё равно не отдавал.

**3. «Исправлено обновлением» проверяется деревом зависимостей, а не номером
версии.** В этом файле было записано «`deepmerge-ts` — исправление доступно
только в Prisma 7». Обновились — уязвимость осталась, а заодно приехали две
новые. Одна команда `npm ls <пакет>` отличает знание от веры.

Общее у всех трёх: инструмент отвечал «всё хорошо», не проверив то, что должен.

### С чего начать новую сессию

```bash
npm run dev:db      # поднять базу данных
npm run ci:quick    # быстрая проверка, ~40 секунд
npm run ci          # 11 проверок, ~10-15 минут, нужен Docker
```

⚠️ `npm run ci` покрывает **7 ворот из 8**. Lighthouse локально не запускается
(падает на Windows в `chrome-launcher`), ZAP сканируется только в PR. Скрипт
печатает это в конце каждого прогона — читайте приписку, а не только «зелёное».

После `npm ci` клиент Prisma генерируется заново автоматически (шаг подготовки
в `scripts/ci-local.mjs`). Без него типы Prisma становятся `any`, и линтер
выдаёт ~140 ошибок в файлах, которых никто не трогал.

## 🖥️ Особенность этой машины

**6 ГБ оперативной памяти** — это мало для связки «Docker + Next.js + браузер».
Практические следствия:

- Сборка и dev-сервер запускаются через `scripts/run-next.mjs` с лимитом кучи 2 ГБ.
  Поменять: переменная `NEXT_MEMORY_LIMIT_MB`.
- Docker Desktop стоит ограничить. Файл `C:\Users\<имя>\.wslconfig`:
  ```ini
  [wsl2]
  memory=2GB
  processors=2
  ```
  После правки: `wsl --shutdown` и перезапуск Docker Desktop.
- Во время сборки полезно закрыть лишние вкладки браузера.

### 🔄 Как теперь проверять работу до отправки на GitHub

Системная причина трёх красных прогонов подряд: пять ворот из восьми
(Gitleaks, Hadolint, Trivy, Checkov, сборка образа) запускались **только**
на GitHub. Узнать их вердикт можно было единственным способом — отправить код.

Теперь они запускаются локально:

```bash
npm run ci          # все ворота, ~5-10 минут, нужен Docker
npm run ci:quick    # быстрая часть, ~40 секунд, без Docker
```

Правило: **зелёный `npm run ci` → зелёный GitHub.** Расхождение само по себе
считается багом. Подробно: `docs/10-how-we-work.md`.
