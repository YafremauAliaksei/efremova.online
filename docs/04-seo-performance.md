# 🚀 04 — SEO и производительность: где жёстко, а где можно выбирать

> Отдельный документ, потому что здесь чаще всего происходит конфликт «красиво ↔ быстро»,
> и решать его нужно заранее, а не в момент, когда дизайнер уже нарисовал видео-фон.

---

## 1. Что означает «100/100 в PageSpeed»

Google оценивает сайт по четырём шкалам. Три из них зависят от аккуратности и берутся почти
автоматически, а одна требует постоянной дисциплины.

| Шкала | Насколько трудно держать 100 | Что решает |
|---|---|---|
| **SEO** | 🟢 легко | теги, разметка, карта сайта — сделали один раз |
| **Accessibility** (доступность) | 🟢 легко | контраст, alt, правильные заголовки |
| **Best Practices** | 🟢 легко | HTTPS, отсутствие ошибок в консоли, заголовки |
| **Performance** | 🔴 **постоянная борьба** | каждый добавленный скрипт отнимает баллы |

Внутри Performance три метрики (Core Web Vitals), и Google учитывает их в ранжировании:

| Метрика | Расшифровка «по-человечески» | Цель |
|---|---|---|
| **LCP** | Через сколько видно главную картинку/заголовок | < 1,8 сек (норма Google — 2,5) |
| **INP** | Насколько быстро сайт отвечает на нажатие | < 150 мс (норма — 200) |
| **CLS** | Прыгает ли вёрстка при загрузке | < 0,05 (норма — 0,1) |

**CLS — самая обидная метрика.** Классический сценарий: вы тянетесь к кнопке, в этот момент
догружается баннер, всё съезжает, и вы жмёте не туда. Лечится тем, что для каждой картинки
заранее указаны ширина и высота — место зарезервировано до загрузки.

## 2. 🔒 Жёсткие правила — нарушать нельзя

Эти пункты защищают одновременно скорость, SEO и безопасность. Если дизайн требует нарушить —
меняем дизайн, а не правило.

| # | Правило | Что сломается при нарушении |
|---|---|---|
| 1 | **Публичные страницы — SSG/ISR**, не SSR | Время ответа с 30 мс вырастет до 300+, минус LCP |
| 2 | **Никаких сторонних скриптов на публичных страницах** | Chat-виджеты и пиксели: −10…−30 Performance, дыра в CSP, вопросы GDPR |
| 3 | **Шрифты только локально** (`next/font`), подмножество символов | Google Fonts = сторонний домен + передача IP третьей стороне = нарушение GDPR (есть судебная практика в ЕС) |
| 4 | **У каждой `<img>` заданы `width` и `height`** | CLS взлетает, Performance падает |
| 5 | **Первый экран — без JS-зависимостей** | LCP уезжает за 2,5 с |
| 6 | **Один `<h1>` на страницу, иерархия заголовков без пропусков** | Accessibility и SEO |
| 7 | **Осмысленный `alt` у каждой картинки** | Accessibility < 100 + потеря поиска по картинкам |
| 8 | **Контраст текста ≥ 4,5:1** | Accessibility < 100. Светло-серый на белом — самая частая ошибка |
| 9 | **Закрытая зона — `noindex` + `no-store`** (сейчас `/admin`, позже кабинет на поддомене) | Утечка персональных страниц в поисковую выдачу. Критично |
| 10 | **Изображения в AVIF с фолбэком WebP** | Вес страницы в 3–5 раз больше |
| 11 | **Бюджет JS первого экрана ≤ 130 КБ (gzip)** | Проверяется в CI, превышение блокирует merge |
| 12 | **Аналитики нет вообще** — ни серверной, ни cookieless | Решение владельца: метрики не нужны. Любой счётчик — это чужой домен в CSP, согласие на куки и минус к скорости |

### 2.1 Откуда взялась цифра 130 КБ

Замер на реальной сборке от 2026-09-14 (`npm run build`):

```
Route (app)                      Size    First Load JS
┌ ƒ /                            347 B        106 kB
├ ƒ /about                       355 B        106 kB
├ ƒ /services                    355 B        106 kB
+ First Load JS shared by all                 103 kB
```

103 КБ из 106 — это базовый рантайм React и Next.js, он одинаков для любой
страницы и уменьшить его нельзя, не отказавшись от фреймворка. Наш собственный
код занимает около 350 байт на страницу.

Поэтому бюджет 90 КБ, записанный при проектировании, был нереалистичным —
он меньше, чем сам фундамент. Честная граница: **130 КБ**, то есть у нас
есть запас примерно 25 КБ на весь интерактив кабинета. Если однажды сборка
покажет больше — это сигнал, что в проект притащили тяжёлую библиотеку,
и разбираться нужно сразу, а не «когда-нибудь потом».

> На балл Performance это не влияет: 100 из 100 достижимо и при 106 КБ,
> потому что этот JS не блокирует отрисовку. Влияет то, **когда** он
> выполняется, а не только сколько его.

## 3. 🎨 Где выбор за вами — красиво против быстро

Здесь нет правильного ответа. Таблица нужна, чтобы вы понимали цену решения.

### 3.1 Анимации

| Вариант | Цена | Вес | Рекомендация |
|---|---|---|---|
| CSS transitions / `@keyframes` | 0 баллов | 0 КБ | ✅ по умолчанию |
| View Transitions API | 0 баллов | 0 КБ | ✅ красивые переходы между страницами бесплатно |
| Framer Motion | −3…−8 Performance | ~50 КБ | 🟡 только в кабинете, не на публичных |
| GSAP + ScrollTrigger | −8…−15 | ~70 КБ | ❌ не для нас |
| Lottie-анимации | −5…−20 | 30 КБ + файл | ❌ статичный SVG решает ту же задачу |

> Дополнительный бонус CSS-анимаций: они автоматически уважают системную настройку
> «уменьшить движение» (`prefers-reduced-motion`) — а это ещё и требование доступности,
> важное для людей с вестибулярными расстройствами. Для сайта психолога — уместно вдвойне.

### 3.2 Изображения

| Вариант | Вес экрана 1920px | LCP | Когда брать |
|---|---|---|---|
| AVIF, качество 70 | ~60 КБ | 🟢 отлично | ✅ основной формат |
| WebP, качество 80 | ~110 КБ | 🟢 хорошо | ✅ фолбэк |
| JPEG, качество 85 | ~280 КБ | 🟡 терпимо | только для старых браузеров |
| PNG | ~900 КБ | 🔴 плохо | только логотипы и иконки |
| Видео-фон (mp4) | 3–8 МБ | 🔴 катастрофа | ❌ запрещено на первом экране |

### 3.3 Стратегия кэширования — свежесть против скорости

| Что | Как кэшируем | Задержка данных | Обоснование |
|---|---|---|---|
| Главная, «Обо мне» | SSG + CDN, 1 год | до передеплоя | меняется раз в месяц |
| Правовые документы | SSG, 1 год | до передеплоя | меняются раз в год |
| Прайс | ISR, 5 минут | до 5 минут | компромисс: цена меняется редко |
| Лекции YouTube | ISR, 6 часов | до 6 часов | API YouTube имеет квоты, чаще ходить нельзя |
| Отзывы | ISR, 1 час | до 1 часа | |
| **Свободные слоты** | **без кэша** | 0 | кэш = двойная запись = конфликт с живым человеком |
| **Кабинет, платежи** | **`no-store`** | 0 | персональные данные вообще не кэшируются |
| Статика (JS/CSS/шрифты) | `immutable`, 1 год | — | имена файлов содержат хеш, старое не покажется |

### 3.4 Шрифты

| Вариант | Цена | Рекомендация |
|---|---|---|
| Системные шрифты | 0 КБ, 0 мс | ✅ идеал по скорости, но сайт «как все» |
| 1 локальный шрифт, 2 начертания, subset | ~25 КБ | ✅ **наш выбор** — характер + скорость |
| 2 шрифта, 5 начертаний | ~120 КБ | 🟡 минус к LCP на мобильных |
| Google Fonts по CDN | +150 мс + риск GDPR | ❌ нет |

## 4. Микроразметка Schema.org — карта внедрения

Разметка — это «перевод» страницы на язык поисковика. За неё Google даёт расширенные сниппеты
(звёзды, цены, время видео), а они дают кликабельность выше на 20–30 %.

| Страница | Типы разметки | Что даст в выдаче |
|---|---|---|
| Главная | `MedicalBusiness` + `Person` + `WebSite` + `SearchAction` | Карточка организации, строка поиска прямо в выдаче |
| Услуги | `Service` + `Offer` + `AggregateRating` | Цены и звёзды в сниппете |
| Лекция | `VideoObject` + `BreadcrumbList` | Превью видео с длительностью |
| Статья | `Article` + `Person` (author) | Дата, автор, картинка |
| Отзывы | `Review` + `AggregateRating` | ⭐ в выдаче |
| Все страницы | `BreadcrumbList` | Путь вместо длинного URL |
| FAQ | `FAQPage` | Раскрывающиеся ответы прямо в Google |

⚠️ **Предупреждение по `MedicalBusiness`.** Тема психологического здоровья попадает в категорию
**YMYL** («Your Money or Your Life») — Google оценивает такие сайты строже по критериям E-E-A-T
(опыт, экспертность, авторитетность, достоверность). Практический вывод: на сайте обязаны быть
реальное имя, номер диплома/лицензии, ссылки на профессиональные ассоциации, физический адрес
практики и контакты. Без этого в ТОП по медицинским запросам не выйти никакими техническими
средствами. Это не про код — это про контент, и это самая важная часть SEO в нашем случае.

## 5. Технический SEO — чек-лист

```
✅ robots.txt с явным Disallow для /api/, /_next/ (кабинет уедет на поддомен со своим robots.txt)
✅ sitemap.xml, генерируется автоматически при сборке + при изменении контента
✅ Канонические URL на каждой странице (защита от дублей)
✅ hreflang для pl / en / ru + x-default
✅ Один язык = один URL (/pl/..., /en/..., /ru/...)
✅ OpenGraph + Twitter Cards, картинка 1200×630 генерируется автоматически
✅ <html lang="pl"> — правильный атрибут языка
✅ Семантический HTML5: header, nav, main, article, section, aside, footer
✅ HTTPS везде, редирект 301 с http и с www
✅ Нет цепочек редиректов (максимум один переход)
✅ 404-страница с полезной навигацией, отдаёт код 404, а не 200
✅ Осмысленные URL: /services/individual-session, не /page?id=42
✅ Google Search Console + Bing Webmaster подключены
✅ Битые ссылки проверяются в CI
```

## 6. Как мы не дадим производительности «сползти»

Главная опасность — не первый запуск, а шестой месяц: добавили виджет, потом ещё один,
и незаметно 100 превратилось в 72. Поэтому проверка автоматическая и блокирующая:

```yaml
# Каждый Pull Request прогоняется через Lighthouse CI
# Порог не достигнут → merge физически невозможен
assertions:
  categories:performance:    ["error", { minScore: 0.95 }]
  categories:accessibility:  ["error", { minScore: 1.00 }]
  categories:best-practices: ["error", { minScore: 1.00 }]
  categories:seo:            ["error", { minScore: 1.00 }]
  total-byte-weight:         ["error", { maxNumericValue: 400000 }]
  largest-contentful-paint:  ["error", { maxNumericValue: 1800 }]
  cumulative-layout-shift:   ["error", { maxNumericValue: 0.05 }]
```

> Почему порог Performance 0.95, а не 1.00: балл слегка «плавает» от нагрузки на машину,
> где запускается тест. 0.95 в CI на практике означает 100 в реальном PageSpeed.
> Доступность, Best Practices и SEO плавать не могут — там требуем ровно 100.

## 7. Реалистичные ожидания по SEO

Чтобы не было разочарования: техническая часть — это фундамент, а не результат.

| Срок | Чего ждать |
|---|---|
| Неделя 1 | Сайт проиндексирован, видно по запросу «имя фамилия психолог» |
| Месяц 1–2 | Позиции по низкочастотным запросам («психолог онлайн Варшава русский язык») |
| Месяц 3–6 | Рост по средним запросам, если регулярно выходит контент |
| Месяц 6–12 | Конкуренция по высокочастотным («психолог онлайн») — нужны ссылки и репутация |

Три вещи, которые дадут больше, чем любая техническая оптимизация:
1. **Регулярные статьи** по реальным вопросам клиентов (2–4 в месяц).
2. **Видео на YouTube** с перелинковкой на сайт — YouTube сам по себе второй поисковик.
3. **Подтверждённая экспертность**: дипломы, членство в ассоциациях, публикации, упоминания.
