# 17. Бэкапы: три места, ключ, восстановление

Вся база — тексты, цены, договоры, картинки (они тоже в базе) — каждую ночь
в 3:00 UTC снимается, сжимается и **шифруется**, а затем лежит в трёх местах:

| Где | Сколько хранится | Кто кладёт |
|---|---|---|
| Том `backups` на сервере | 14 дней | контейнер `backup` сам |
| S3-совместимое хранилище другого поставщика (Cloudflare R2 или Backblaze B2) | 30 дней | контейнер `backup` сам |
| Офлайн-диск дома | сколько захотите | владелец, раз в 2 недели |

Сервер — один физический компьютер, хранилище — другой поставщик и другие
машины, домашний диск — офлайн, до него не достать ни через интернет, ни
через взлом сервера.

## Ключ шифрования

Шифрование — [age](https://age-encryption.org), парой ключей:

- **публичный** (`age1…`) лежит на сервере (`BACKUP_AGE_PUBLIC_KEY` в `.env`):
  им можно только зашифровать;
- **приватный** у сервера не бывает никогда: взломанный сервер не расшифрует
  ни одного старого бэкапа, и из хранилища их тоже не прочитать.

Один раз, на домашнем компьютере:

```bash
age-keygen -o backup.key                 # печатает публичный ключ — в .env сервера
age -p -o backup.key.age backup.key      # шифрует сам ключ паролем
rm backup.key                            # в открытом виде ключ не хранится
```

`backup.key.age` — файл, бесполезный без пароля. Хранить в **трёх местах**:
домашний диск с бэкапами, флешка в другом месте, облачный диск или менеджер
паролей. Пароль — в менеджере паролей и на бумаге. Потеряны и ключ, и пароль —
бэкапы не восстановить никому, включая владельца.

## Хранилище (Cloudflare R2 — 10 ГБ бесплатно)

1. R2 → Create bucket `efremova-backups` (регион — Eastern Europe или Auto).
2. R2 → Manage API tokens — **два** токена, оба только на этот бакет:
   - «Object Read & Write» — для сервера: `BACKUP_S3_ACCESS_KEY_ID`,
     `BACKUP_S3_SECRET_ACCESS_KEY`, `BACKUP_S3_ENDPOINT`, `BACKUP_S3_BUCKET` в `.env`;
   - «Object Read only» — для домашнего компьютера (скачивать офлайн-копию).
3. Healthchecks.io → новая проверка «бэкап», период 1 день → адрес в
   `BACKUP_HEARTBEAT_URL`. Бэкап не прошёл ночью — Healthchecks напишет.
   Свежесть бэкапа дополнительно проверяет сторож сервера (docs/16).

## Офлайн-копия — раз в 2 недели

Скачать из хранилища новые файлы `efremova-*.sql.gz.age` и `.sha256` рядом
(в R2 — через панель или любой S3-клиент, ключом «только чтение») на домашний
диск и сверить контрольную сумму:

```bash
sha256sum -c efremova-20261103-030000.sql.gz.age.sha256
```

Healthchecks: отдельная проверка «офлайн-копия» с периодом 15 дней — после
каждой выгрузки открыть её адрес пинга; забыли — напомнит.

## Восстановление — на любом сервере

```bash
age -d -o backup.key backup.key.age                       # спросит пароль
age -d -i backup.key efremova-…sql.gz.age | gunzip > dump.sql
rm backup.key
docker compose up -d postgres                             # пустая база
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < dump.sql
docker compose up -d                                      # остальное
rm dump.sql                                               # открытый дамп не хранить
```

Миграции в дампе уже отмечены как выполненные — приложение стартует сразу.

**Учение раз в квартал**: то же самое на домашнем компьютере в Docker, с
последним бэкапом. Бэкап, который ни разу не восстанавливали, бэкапом не
считается. Дату учения — в PROJECT_LOG.md.
