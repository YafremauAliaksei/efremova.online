# 🔎 14 — Разбор: как отдавать сайт-визитку

> Разбор от 2026-10-25. Вопрос владельца: если итоговый план — страницы,
> которые отдаёт кэш Cloudflare, не избыточен ли нынешний подход, и нет ли
> способа проще, но не менее безопасного для обычного сайта-визитки.
>
> Короткий ответ: **да, публичная часть устроена тяжелее, чем нужно, и при
> этом её нельзя кэшировать.** Предлагается отдавать посетителю чистый HTML
> без JavaScript. Это проще, быстрее, кэшируется Cloudflare и по защите
> строже нынешнего. Админка остаётся как есть.
>
> **Сделано (задача 9, 2026-10-25):** публичные страницы — HTML без
> JavaScript, вариант C ниже. После переделки: 0 скриптов, страница вместе
> со стилями — 16–18 КБ, Lighthouse 100 по всем четырём категориям.
> Решения владельца по п.6 — там же.

## 1. Как сейчас — замеры

Главная `/ru`, локальная сборка (`npm run build`, `next start`, база с сидом):

| Что                       | Сейчас                                                  |
| ------------------------- | ------------------------------------------------------- |
| `Cache-Control`           | `private, no-cache, no-store, max-age=0, must-revalidate` |
| CSP                       | новый nonce на каждый запрос                            |
| HTML                      | 30 КБ                                                   |
| `<script>` на странице    | 20, из них 12 встроенных                                |
| JavaScript                | 474 КБ, 147 КБ в gzip                                   |
| Обращений к базе          | на каждого посетителя                                   |

Интерактивность публичной части — **одна**: переключатель языка запоминает
выбор в cookie по щелчку. Всё остальное — текст, картинки и ссылки.
147 КБ скриптов уходят посетителю ради одной строки `document.cookie`.

### Почему так вышло

Публичные страницы помечены `force-dynamic` по двум причинам (docs/13 п.6.1):

1. **CSP с nonce.** Next.js вставляет в каждую страницу встроенные скрипты
   (данные для «оживления» React). Без `'unsafe-inline'` их пропускает только
   nonce, а nonce — новый на каждый ответ. Значит, страницу нельзя собрать
   заранее и нельзя положить в общий кэш: в кэше застрял бы чужой nonce.
2. **Цена по стране.** Услуги читают заголовок `CF-IPCountry` и показывают
   цену региона. Страница зависит от посетителя — общий кэш её не держит.

Итог: план «Cloudflare отдаёт кэш» с нынешним устройством **несовместим**.
Каждый посетитель идёт до ноутбука, и ноутбук каждый раз ходит в базу.

| --------------------------------------------- | ----------------------------- |

состояния в браузере, React на стороне посетителя.

## 3. Варианты

| Вариант | Что это | Кэш Cloudflare | Защита от XSS | JS у посетителя | Работы |
| --- | --- | :---: | --- | --- | --- |
| **A. Как есть** | `force-dynamic`, nonce на запрос | ❌ | сильная (nonce) | 147 КБ | 0 |
| **B. Next ISR + `'unsafe-inline'`** | страницы собираются заранее, CSP без nonce | ✅ | слабее: встроенный скрипт пройдёт | 147 КБ | ~1 PR, мало кода |
| **C. Чистый HTML без JS** ⭐ | публичные адреса отрисовываются сервером в HTML без скриптов | ✅ | **сильнее нынешней**: `script-src 'none'` | **0** | ~2 PR |
| **D. Отдельный генератор статики** | Astro / `next export` пересобирает сайт при сохранении | ✅ | `script-src 'none'` | 0 | много: второй проект, сборка по кнопке |

- **B** — самый дешёвый путь к кэшу, но это ослабление CSP, которое правило 5
  CLAUDE.md запрещает. И 147 КБ ненужного JavaScript остаются.
- **D** даёт то же, что C, ценой второго инструмента сборки, шага «опубликовать»
  и рассинхрона между админкой и сайтом. Для визитки — перебор.
- **C** — рекомендуемый вариант, подробно ниже.

## 4. Вариант C: как устроен

### 4.1 Отрисовка

Публичные адреса (`/ru`, `/pl/about`, `/en/services`…) перестают быть
страницами App Router. Их отдаёт один обработчик маршрута (`route.ts`). Он
берёт данные из базы и отрисовывает **те же компоненты** через
`prerender` из `react-dom/static` (React 19). Результат — HTML-строка
без единого `<script>`.

Проверено пробой на текущих версиях пакетов:

- `prerender` отрисовывает асинхронные компоненты (наши блоки сами ходят
  в базу) — **0 скриптов** в результате;
- текст экранируется: `<script>` из базы становится `&lt;script&gt;`;
- стили Tailwind собираются в один файл через уже установленные `postcss` и
  `@tailwindcss/postcss` — 21 КБ, без новых зависимостей.

Зависимостей от Next в публичных компонентах немного: `next/link` → обычный
`<a>`, `headers()` → параметр, `notFound()` → ответ 404. `next/image` нигде
не используется — картинки уже идут через свой `<picture>`.

### 4.2 Заголовки

```
Cache-Control: public, max-age=0, must-revalidate
CDN-Cache-Control: public, max-age=3600, stale-while-revalidate=86400, stale-if-error=86400
Content-Security-Policy: default-src 'none'; script-src 'none'; style-src 'self';
  img-src 'self'; font-src 'self'; connect-src 'self'; frame-src 'none';
  object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
```

- Кэш раздельный (RFC 9213): Cloudflare держит страницу час, браузер каждый
  раз сверяется с Cloudflare. Своя копия в браузере на пять минут показывала
  бы старый текст сразу после правки — так упал браузерный тест админки,
  и так же это увидел бы владелец.
- `connect-src 'self'`, а не `'none'`: Lighthouse читает `robots.txt`
  запросом изнутри страницы и с `'none'` ставил SEO 0,91. Скриптов на
  странице нет — запросов посетителю делать нечем.
- `script-src 'none'` — на странице не выполняется **никакой** скрипт, даже
  свой. Внедрённому `<script>` нечего обходить: nonce не нужен.
- `style-src 'self'` без `'unsafe-inline'` — встроенных стилей в публичных
  компонентах нет. Сейчас `'unsafe-inline'` для стилей разрешён; здесь он уходит.
- Политика одна для всех посетителей, поэтому страницу можно кэшировать.
- Правило 5 (ни одного чужого домена) сохраняется без изменений.

Админка остаётся на App Router: nonce, `no-store`, `noindex`, как сейчас.

### 4.3 Кэш и свежесть

| Слой        | Поведение |
| ----------- | --------- |
| Cloudflare  | держит страницу час (`CDN-Cache-Control: max-age=3600`); пока обновляет — отдаёт прежнюю |
| Ноутбук     | отрисовывает страницу, только когда Cloudflare спросил: несколько раз в час на страницу, а не на каждого посетителя |
| Правка в админке | видна через ≤ 1 ч (сброс кэша Cloudflare не нужен — п.6) |
| Ноутбук выключен | Cloudflare час отдаёт последнюю копию, `stale-while-revalidate` растягивает это на сутки |
| База не отвечает | страница собирается на заглушках и отдаётся с `no-store`: урезанная копия не вытесняет нормальную в кэше Cloudflare |

Последний пункт — побочная выгода для сервера на ноутбуке: короткий простой
посетители не заметят.

### 4.4 Что меняется для посетителя

| Было | Станет |
| --- | --- |
| переключатель языка ставит cookie скриптом | обычные ссылки; выбор запоминает адрес `/api/lang?to=/pl/about`: сервер ставит cookie и отвечает 303 с `no-store` |
| цена по стране (`CF-IPCountry`) | общая цена; выбор валюты посетителем — задача 9a (п.6) |
| «не найдено» рисовалось только скриптом (T.8) | 404 на языке адреса — обычный HTML |
| переходы без перезагрузки | обычные переходы; страницы по 5–15 КБ из ближайшего узла Cloudflare — разницы не видно |

### 4.5 Что остаётся как есть

- админка целиком: вход по ссылке и коду, журнал, пределы записи, конструктор;
- база, схема, правовые документы, картинки (`/media/<хеш>` и так кэшируются навсегда);
- middleware: ловушки, CSRF, гейт админки, переброс на язык.

## 5. Безопасность: стало ли слабее

Нет — строже по каждому пункту, который касается посетителя:

| Угроза | Сейчас | Вариант C |
| --- | --- | --- |
| Внедрённый скрипт (XSS) | заблокирован nonce | заблокирован `script-src 'none'`: скрипты не выполняются вообще |
| Внедрённый стиль | разрешён (`'unsafe-inline'`) | запрещён |
| Чужие домены | запрещены | запрещены |
| Отравление кэша | кэша нет | страница не зависит от посетителя: ни cookie, ни страны, ни nonce в ней нет |
| Нагрузка на ноутбук (DoS) | каждый запрос до базы | Cloudflare гасит повторные запросы |
| Админка | nonce, `no-store` | без изменений |

Единственное новое требование: в публичный HTML **никогда** не должно попадать
ничего, что зависит от посетителя. Его стоит закрепить тестом: две отрисовки
одной страницы с разными заголовками запроса дают одинаковый HTML.

## 6. Решения владельца (2026-10-25)

1. **Цена.** По умолчанию — злотые; рядом выбор валюты: евро, российский
   и белорусский рубль и любая другая, какую владелец добавит. Цены в каждой
   валюте владелец ставит вручную ровными числами (200 zł, 45 €), а не
   пересчётом по курсу; админка подсказывает текущий курс из 1–2 запросов
   к публичному API. История цен публична: архив «в июне 2026 цена была
   такой-то», правка старой цены запрещена так же, как у договора.
   Выбор валюты без JavaScript — ссылками `?currency=EUR`: Cloudflare кэширует
   каждый такой адрес отдельно. Задачи 9a и 9b в PROJECT_LOG.
2. **Cookie выбора языка — нужна:** язык определился по браузеру, человек
   переключил на русский — дальше сайт открывается по-русски. Сделано
   адресом `/api/lang` (п.4.4).
3. **Токен Cloudflare не нужен.** Цена меняется раз в полгода, договор
   заключается после обсуждения цены — час старого кэша ничему не мешает.
   Проще и безопаснее без лишнего секрета на сервере.

## 7. Что ещё в репозитории избыточно для визитки

Инвентаризация: что работает, что лишнее, что делать.

| Что | Состояние | Предложение |
| --- | --- | --- |
| Таблицы `lectures`, `lecture_categories` | ни одного обращения в коде; кэш YouTube API, который не планируется (видео — блоки с обложкой) | убрать миграцией: схема обещает «только то, что работает» |
| `ip_blocklist`, поле `pushedToCloudflare` | только очистка просроченных; автоблокировка (T.6) не начата | заморозить T.6: при кэше Cloudflare и его WAF до ноутбука доходит мало; решить после развёртывания |
| Ловушки (honeypot): ~960 строк в `src/lib/security` + middleware | работают, покрыты тестами, нагрузку держат пределы | не развивать дальше; с кэшем до них доходят только запросы мимо кэша |
| `revalidatePath` в действиях админки | сбрасывает кэш Next, которого у публичных страниц при `force-dynamic` нет | в варианте C — заменить сбросом кэша Cloudflare (или убрать) |
| 147 КБ JS на публичных страницах | см. п.1 | уходит с вариантом C |
| CI: 9 ворот, ~5 минут на прогон | работает | оставить; самые долгие — DAST и Lighthouse (по ~3 мин, параллельно) |
| Админка: 2FA, журнал с цепочкой хешей, пределы записи | соразмерно: это единственная дверь к сайту | оставить |
| Правовые документы, отзывы с датой согласия | требования польского права и GDPR | оставить |

Ничего из этого не опасно. Это код, который надо сопровождать, а пользы
визитке он почти не даёт.
