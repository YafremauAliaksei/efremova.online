# 🏛️ 13 — Архитектура сайта: страницы, блоки, языки, кэш

> Этот документ отвечает на вопрос «как сайт устроен и почему именно так».
> Он появился 2026-09-14, когда цель проекта сузилась и стала честной:
> **сначала — сайт-визитка, который выполняет одну задачу.**

---

## 1. Что мы строим и чего не строим

**Задача сайта, сформулированная владельцем:**

> «Просто сделать его одним из сайтов, который выпадают в выдаче, и с помощью
> которого клиент найдёт для себя контактные данные психолога».

Всё остальное — не задача. Ни миллион метрик, ни реклама, ни личный кабинет.

| Строим                                                | Не строим                    |
| ----------------------------------------------------- | ---------------------------- |
| Красивый быстрый сайт на трёх языках                  | Аналитику любого вида        |
| Контакты в один клик: почта, Telegram, WhatsApp, Viber | Рекламу и любые трекеры      |
| Страницы, которыми владелец управляет сам из админки  | Личный кабинет и авторизацию |
| Записи с YouTube-канала как карточки на своём домене  | Встроенный плеер YouTube     |
| Отзывы                                                | Форму «оставьте отзыв»       |

### 1.1 Главное архитектурное обещание: самодостаточность

**Браузер посетителя не обращается ни к одному чужому домену.** Ни за шрифтом,
ни за картинкой, ни за скриптом, ни за кадром. Политика безопасности
(`src/lib/security/headers.ts`) это не просто декларирует, а **запрещает
технически**: `default-src 'self'`, `frame-src 'none'`, `connect-src 'self'`.

Три выгоды сразу, и ни одна не является «строгостью ради строгости»:

| Выгода             | Как это работает                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **Приватность**    | IP посетителя не уходит третьим лицам. Значит, согласия на это не требуется, и в политике конфиденциальности нечего скрывать |
| **Безопасность**   | Взлом чужого сервера не превращается во взлом нашего сайта. Именно так ломают через рекламные сети, счётчики и виджеты       |
| **Скорость**       | Ни одного лишнего DNS-запроса и TLS-рукопожатия. Это десятки миллисекунд на каждого посетителя                               |

Практическое следствие: обложки роликов с YouTube **скачиваются к себе** и
отдаются со своего домена. Картинка, подгруженная с сервера Google, сообщила бы
Google IP каждого посетителя ещё до того, как тот что-либо нажал.

## 2. Карта сайта и адреса

```
/                    главная
/about               обо мне
/services            услуги и цены
/contacts            контакты          ← ради этой страницы всё затевалось
/video               записи с канала   ← за переключателем
/privacy /terms      правовые документы
```

**Адреса латиницей по-английски.** Правило простое: либо кириллица для русского,
либо латиница для языка, который ею пишется. Смесь вроде `/o-mne` не является
ни тем, ни другим. Английские адреса одинаковы для всех трёх языков —
переводить сам адрес незачем, поисковики берут язык из содержимого страницы
и из разметки `hreflang`.

## 3. Три языка: русский, польский, английский

### 3.1 Адреса

Каждый язык живёт по своему адресу. Русский — язык по умолчанию:

| Язык      | Главная | Внутренняя страница |
| --------- | ------- | ------------------- |
| Русский   | `/ru`   | `/ru/about`         |
| Польский  | `/pl`   | `/pl/about`         |
| Английский | `/en`   | `/en/about`         |

**Почему не «три текста в одной странице».** Поисковик индексирует адреса,
а не куски текста внутри страницы. Если по адресу `/about` лежат сразу три
языка, Google видит одну страницу со смешанным языком: он не покажет её
польской выдаче по польскому запросу, а русской — по русскому. Разметка
`hreflang`, которая связывает языковые версии между собой, тоже требует
разных адресов.

Мгновенность переключения при этом не теряется: Next.js заранее подгружает
страницу, на которую ведёт ссылка, поэтому смена языка — не перезагрузка,
а подстановка уже загруженного содержимого.

### 3.2 Переброс без префикса

Адрес без языка перебрасывает на язык:

```
efremova.online           →  efremova.online/ru
efremova.online/about     →  efremova.online/ru/about
```

Если человек **сам выбрал** другой язык — переброс идёт на его язык.

Три требования к этому перебросу, и каждое важно:

1. **Код 307, а не 301.** Постоянный переброс (301) браузер запоминает навсегда,
   и человек больше никогда не сможет сменить язык — его будет уносить на старый.
   Временный (307) такого не делает.
2. **Ответ помечается `no-store`.** Переброс зависит от конкретного посетителя,
   поэтому его нельзя класть в общий кэш — иначе поляк получит чужой русский.
   Сами страницы, куда он ведёт, кэшируются полностью (раздел 6).
3. **Никакого автоперехода по стране.** Google прямо предупреждает: принудительный
   переброс по языку мешает ему обойти остальные версии, а человека запирает
   в версии, которую он не выбирал. Вместо этого — узкая полоска сверху:
   «Ta strona jest dostępna po polsku →». Не нажал — ничего не произошло.

### 3.3 Слэш в конце

`efremova.online/pl` и `efremova.online/pl/` обязаны быть **одним адресом**,
а не двумя. Иначе поисковик считает их разными страницами с одинаковым текстом,
и обе теряют в позициях.

Решение: канонический вид — **без слэша**, адрес со слэшем перебрасывается
на него постоянным кодом 308. Плюс на каждой странице тег `<link rel="canonical">`,
который прямо называет правильный адрес.

### 3.4 Определение языка и cookie

| Источник                  | Что это                                                     | Требует ли согласия                                   |
| ------------------------- | ----------------------------------------------------------- | ----------------------------------------------------- |
| `Accept-Language`         | браузер сам присылает список языков в каждом запросе        | **нет** — мы ничего не храним, это часть запроса      |
| `CF-IPCountry`            | страна, которую подставляет Cloudflare                      | **нет**, если не сохраняем. Упоминается в политике    |
| Cookie с выбранным языком | «этот человек выбрал польский»                              | **нет** — исключение «настройка интерфейса»           |

Ключевое правило, которое делает всё это чистым:

> **Cookie не ставится, пока человек сам не щёлкнул переключатель языка.**

Определение работает без всякого хранения. А cookie, поставленная **по прямому
действию человека** ради запоминания его же выбора интерфейса, попадает под
исключение из требования согласия (ePrivacy, ст. 5(3) — «строго необходимое
для услуги, явно запрошенной пользователем»; толкование WP29, заключение
04/2012, раздел про cookie настройки интерфейса).

⚠️ Это стандартное прочтение, но окончательное слово — за юристом, который
проверяет правовые тексты (PROJECT_LOG, блокер про юридическую проверку).

### 3.5 Значение языка — это данные, а не код

Язык приходит из адреса, из заголовка или из cookie — то есть **снаружи**.
Ни одно из этих значений не попадает никуда напрямую.

```
разрешено ровно три значения: 'ru' | 'pl' | 'en'
всё остальное → язык по умолчанию, без ошибки и без записи в лог
```

Проверка стоит **одна на весь проект**, в одном месте. Подделанная cookie
`lang=<script>` не превращается ни в текст на странице, ни в путь к файлу,
ни в имя ключа перевода: она просто не проходит список и заменяется на `ru`.

## 4. Страницы собираются из блоков, и блоками управляет владелец

Требование владельца: количество экранов, количество страниц и вид шапки
должны настраиваться **из базы**, без правки исходников.

### 4.1 Устройство

```
Page          адрес, вкл/выкл, название в меню, порядок,
              показывать в шапке / в подвале, заголовок для поисковика
 └ PageBlock      тип, порядок, вкл/выкл, оформление, содержимое
     └ BlockRevision   снимок содержимого при каждом сохранении
MediaAsset    загруженные картинки
```

Типы блоков объявлены **в коде**: `hero`, `text`, `text+фото`, `услуги`,
`видео`, `отзывы`, `контакты`, `призыв`. Новый тип блока — правка репозитория
и новая версия сайта. База хранит только то, **какие блоки на какой странице
стоят, в каком порядке и с каким содержимым**.

Это и есть граница: **в базе данные, в коде — как их рисовать.**

### 4.2 Четыре правила, которые делают это безопасным

Ровно здесь ломают сайты на готовых движках, поэтому правила не обсуждаются.

**1. У каждого типа блока — своя схема проверки.**
Содержимое из базы проходит через неё перед отрисовкой. Не прошло — блок
пропускается, остальная страница живёт дальше. Испорченная запись в базе
роняет один блок, а не весь сайт.

**2. Неизвестный тип блока молча пропускается.**
Откатили версию сайта, а в базе остался блок нового типа — страница откроется,
просто без него. Не ошибка 500 на весь сайт.

**3. Текст выводится как текст. Всегда.**
`dangerouslySetInnerHTML` в проекте **не используется ни разу** — это
проверяемое утверждение. Даже если кто-то запишет `<script>` прямо в базу,
на странице появятся буквы `<script>`, а не тег. Форматирование (жирный,
курсив, ссылка, список) делает наш собственный код по ограниченному набору
правил, а не подстановка чужой разметки.

> Это прямой ответ на историю владельца: сайт на WordPress взломали через
> уязвимость в шаблоне темы. Шаблон темы там **исполняет код**, и дыра в нём
> превращается в захват сайта. Здесь исполняемого кода в содержимом нет
> в принципе.

**4. Оформление — набор вариантов, а не произвольные значения.**

| Поле         | Допустимые значения                       |
| ------------ | ----------------------------------------- |
| ширина       | `узкий` · `широкий` · `во всю ширину`     |
| выравнивание | `слева` · `по центру`                     |
| фон          | `основной` · `оттенённый`                 |

Не «80%» и не «640px». Причина двойная: произвольное число из базы попадает
в стили страницы — это и путь сломать вёрстку одной опечаткой, и потенциальная
дыра. А ещё набор вариантов удерживает сайт в едином виде: страница, собранная
из четырёх разных ширин, выглядит как самоделка.

## 5. Ничего не удаляется

Требование владельца, и оно правильное: случайно стёртый текст — это потеря,
которую не возместить. Защиты две, независимые.

**Архив вместо удаления.** Кнопка «Удалить» в админке переводит блок или
страницу в архив: `archivedAt` заполняется, с сайта объект исчезает, из базы —
нет. Отдельный экран «Архив» показывает всё убранное с кнопкой «вернуть».
Настоящее удаление строки не делает ни одна кнопка админки.

**История правок.** Каждое сохранение кладёт снимок прежнего содержимого
в `BlockRevision`. Промахнулись мышью, стёрли абзац, нажали «Сохранить» —
предыдущая версия на месте, рядом кнопка «вернуть как было».

Третий рубеж — ночная резервная копия базы (раздел 7 и `docs/03`).

## 6. Кэширование

Исходные данные, названные владельцем: 30–40 посетителей в день, цена меняется
раз в полгода, новое видео — раз в неделю, устаревание на час-два приемлемо.

При таких числах ходить в базу на каждого посетителя незачем.

| Слой                  | Настройка                                              | Что даёт                                                                |
| --------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------- |
| Next.js               | страницы собираются заранее, пересборка раз в час      | посетитель **не** дёргает базу вообще                                   |
| Сохранение в админке  | пересборка затронутых страниц немедленно               | правка видна через секунды, а не через час                              |
| Cloudflare            | `s-maxage=3600` + «отдавай устаревшее, пока обновляешь» | почти все посетители получают ответ от ближайшего к ним сервера          |

Ноутбук при таком раскладе обслуживает не 40 человек в день, а несколько
запросов от Cloudflare в час.

### 6.1 Что сейчас не так

`src/app/page.tsx` помечен `force-dynamic`: страница собирается заново **на
каждого посетителя** и на каждого ходит в базу. Причина — чтение страны из
заголовка ради валюты.

При этом админка вызывает `revalidatePath('/')` — сброс кэша, которого при
`force-dynamic` не существует. Одно противоречит другому.

Чинится вместе с языковыми префиксами: страница становится заранее собранной,
а переключатель валюты уезжает на сторону браузера.

### 6.2 Сообщать ли Cloudflare, что страница изменилась

Можно: один запрос к их API при сохранении, и кэш сбрасывается мгновенно.
Но при частоте правок «дважды в неделю» час устаревания владелец сам назвал
приемлемым.

Решение: **выключаемая возможность**. Есть токен в `.env` — сбрасывает сразу;
нет токена — просто ждём час. Самодостаточность сайта при этом не страдает:
это исходящий запрос сервера, никаких данных посетителей в нём нет, и
в браузер он не попадает.

## 7. Картинки

### 7.1 Только пиксели, никаких векторов

**SVG не принимается ни в каком виде.** SVG — это не картинка, а программа
для рисовальщика: XML с вложенным скриптом, ссылками и произвольной геометрией.
Владелец привёл точный пример — стикер, который ломал приложение количеством
вершин в фигуре. Суть та же: вектор исполняется, а исполняемому содержимому
от посторонних здесь места нет.

### 7.2 Что происходит с загруженным файлом

| Шаг                                        | Зачем                                                              |
| ------------------------------------------ | ------------------------------------------------------------------ |
| ограничение размера **до** чтения файла    | не дать съесть память одним файлом                                 |
| проверка первых байт, а не расширения      | `.jpg` ничего не значит, содержимое значит                         |
| принимаем только JPEG, PNG, WebP, AVIF     | остальное — отказ без разговоров                                   |
| ограничение числа пикселей до распаковки   | защита от «архивной бомбы»: 2 МБ разворачиваются в 40 000 × 40 000  |
| пересборка в WebP и AVIF в нескольких размерах | вес, скорость **и стирание EXIF**                              |
| имя генерируем сами, по отпечатку содержимого | загруженное имя не касается файловой системы                    |

**Про EXIF отдельно.** Фотография с телефона несёт координаты места съёмки.
Фото психолога, сделанное дома, публикует домашний адрес. Пересборка стирает
это целиком — и это, пожалуй, главный довод за то, чтобы никогда не публиковать
загруженный файл как есть.

Библиотека пересборки — `sharp` (внутри libvips). У libvips бывали уязвимости;
мера против них — ограничения выше плюс контейнер с файловой системой только
для чтения.

### 7.3 Где они лежат — и честно про бэкапы

Картинки хранятся **в базе данных**, отдаются через маршрут с вечным кэшем
(имя файла — отпечаток содержимого, значит содержимое по этому адресу никогда
не меняется).

Выгода: резервная копия — **один зашифрованный файл**, в котором есть всё;
контейнеру не нужен ни один каталог с правом записи.

⚠️ **Честно про опасение владельца.** `pg_dump` не умеет докидывать только
изменения — он каждый раз выгружает базу целиком. То есть картинки в базе
действительно попадают в каждую ночную копию.

Почему это всё равно нормально **при нашем масштабе**: десятки картинок,
пересобранных под веб, — это единицы мегабайт. Ночная копия на 10 МБ,
тридцать копий — 300 МБ. Для любого диска это ничто.

**Граница, после которой решение меняется:** суммарный вес картинок больше
**50 МБ**. Тогда они переезжают на диск, а резервное копирование — на
инструмент с настоящим докидыванием изменений (`restic`: шифрует, дедуплицирует,
копирует только новое). Это записано здесь, чтобы вопрос всплыл сам, а не
через год в виде «почему бэкап идёт сорок минут».

## 8. Отзывы

Здесь есть ловушка, о которой надо знать до того, как отзыв появится на сайте.

**Отзыв на сайте психолога сообщает, что конкретный человек был клиентом
психолога.** По GDPR это данные о здоровье — статья 9, самая строгая категория.

Отсюда:

- согласие должно быть **явным, отдельным и доказуемым**. «Она не возражала» —
  не согласие;
- отозвать согласие можно в любой момент, и отзыв обязан исчезнуть сразу;
- псевдоним не спасает, если человека можно узнать по деталям.
  «Анна, 34, преподаватель скрипки из Гданьска» — это идентификация.

**Как делаем:** отзывы обезличенные («клиентка, 34 года, тревожность»),
согласие берётся **вне сайта** — письмом или на бумаге, — а в базе хранится
только псевдоним, текст, отметка о согласии и его дата.

**Чего не делаем:** формы «оставьте отзыв» на сайте. Она превратила бы владельца
в сборщика данных о здоровье от незнакомых людей без всякой проверки.

Отзывы показываются в двух местах: несколько на главной и все — на отдельной
странице.

## 9. Аналитики нет. Атаки видно

Аналитики нет вообще — ни внешней, ни своей. Это решение владельца, и оно же
экономит согласие на cookie, чужой домен в политике безопасности и вес страницы.

Но «когда меня ддосят» видеть надо. Для этого три источника, и ни один не
требует чужих скриптов на странице:

| Где                      | Что показывает                                        |
| ------------------------ | ----------------------------------------------------- |
| Панель Cloudflare        | кто, откуда, сколько — включая отбитые атаки          |
| Таблица `honeypot_hits`  | кто лез на `/wp-admin`, `/.env`, `/phpmyadmin`        |
| Таблица `security_events` | отказы проверки источника, аномалии                   |

### 9.1 Как это устроено, чтобы защита не стала уязвимостью

До 2026-09-14 попадания не записывались вовсе: обработчиков не существовало,
а вдобавок наша же проверка от CSRF отвечала 403 на внутренний вызов. Две
ошибки, наложенные друг на друга (ветка `fix/security-events`).

Но простое «починить запись» создало бы дыру крупнее той, что закрывало.
Каждое попадание в ловушку стоило бы нам трёх вещей:

| Что | Во что превращается при 1000 запросов в секунду |
| --- | --- |
| ещё один HTTP-запрос к себе, чтобы записать событие | **атака удваивается сама**: 1000 снаружи → 2000 внутри |
| ожидание 2–5 секунд перед ответом | через пять секунд висит 5000 соединений — лимит кончится у нас раньше, чем терпение у атакующего |
| строка в базе на каждое попадание | 3,6 миллиона строк за час |

Поэтому запись устроена так:

1. **Ограничитель** (`src/lib/security/throttle.ts`) — три независимых предела:
   не чаще одной записи на адрес в минуту, общий потолок 120 записей в минуту,
   не больше 5000 отслеживаемых адресов. Повторное попадание получает
   мгновенный 404 — без ожидания и без внутреннего вызова.
2. **Склейка в базе** — строка на «адрес + тип ловушки + час» со счётчиком.
   Первая запись сохраняет снимок запроса, дальше растёт только число.
3. **Инцидент** — при 50 попаданиях за 5 минут один раз пишется «чёрный ящик».

Замерено на живом сервере: **31 обращение к ловушке → одна строка со счётчиком
31**. Первое обращение заняло 3 секунды, остальные — по 20 миллисекунд.

**Почему это важнее ротации логов.** Ограничение логов по размеру не может
сохранить начало атаки: объём задаёт атакующий, а размер буфера — мы, и при
достаточном потоке начало всегда вытесняется. Склейка сохраняет: первая строка
создаётся первым запросом и дальше не перезаписывается.

### 9.2 Задержка ответа осталась, но только на первом попадании

Задержка 2–5 секунд задумывалась, чтобы тратить время сканера. Но сканер ответа
не ждёт — он шлёт следующий запрос немедленно. Ждали **мы**, своими соединениями.

Теперь задержку получает только то попадание, которое записывается. Одиночный
сканер по-прежнему тормозится на каждом новом типе ловушки; поток — нет.

## 10. Два домена

| Домен                     | Что там                                        | Где работает      |
| ------------------------- | ---------------------------------------------- | ----------------- |
| `efremova.online`         | сайт-визитка. Ни одной таблицы с личными данными | ноутбук с Debian  |
| `cabinet.efremova.online` | вход, запись, платежи, заметки                 | VPS в ЕС          |

Единственное, что связывает их, — ссылка в шапке основного сайта. Пока кабинета
нет, эта ссылка просто не показывается: она такая же секция, как страница
с видео, и выключается тем же переключателем.

**Почему не «просто закрыть кабинет паролем».** На визитке кода, читающего
личные данные, нет вовсе — ни таблиц, ни моделей, ни маршрутов. Не «закрыто»,
а «не существует». Из того, чего нет, утечь нечему.

**Как это проверяется на своей машине.** Браузеры сами разрешают `*.localhost`
в `127.0.0.1` — файл `hosts` править не нужно:

```
http://localhost:3000          основной сайт
http://cabinet.localhost:3000  кабинет
```

Приложение смотрит на заголовок `Host` и понимает, кем ему быть. Разделение
доменов видно в работе задолго до появления сервера.
