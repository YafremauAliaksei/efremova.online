# 16. Сторож сервера: оповещения о сбоях

Наблюдение — на уровне сервера, не сайта: владелец узнаёт о беде сам, не
заходя в админку. Сторож — контейнер `watchdog` в `docker-compose.yml`, код —
`scripts/watchdog/` (без зависимостей, покрыт тестами).

## Что проверяется — раз в минуту

| Проверка | Сбой, если |
|---|---|
| Сайт снаружи — `APP_URL/api/health` через Cloudflare и туннель | нет ответа, ошибка, медленнее `WATCHDOG_SLOW_MS` (5 с) |
| Приложение изнутри — `app:3000/api/health` (заодно база) | то же |
| Диск сервера | занят больше `WATCHDOG_DISK_PERCENT` (85 %) |
| Память сервера | занята больше `WATCHDOG_MEMORY_PERCENT` (90 %) |
| Нагрузка (среднее за 5 минут) | больше `WATCHDOG_LOAD_PER_CPU` × число ядер (2×) |
| Бэкап | последний успешный старше 26 часов |

Сообщение приходит при **сбое** и при **восстановлении**; пока сбой держится —
напоминание раз в 6 часов, не каждую минуту. Раз в сутки (`WATCHDOG_SUMMARY_HOUR_UTC`,
по умолчанию 7:00 UTC) — сводка по всем проверкам. При запуске — «Сторож запущен»:
видно, что каналы работают, и что сервер перезагружался.

Если сервер умер целиком (нет питания, нет интернета), сторож не скажет ничего —
поэтому каждый круг он шлёт **пульс** во внешний сервис. Тишина дольше 5 минут —
и уже внешний сервис пишет владельцу.

## Каналы — что задано в `.env`, туда и уходит

**Telegram**
1. В Telegram — @BotFather → `/newbot` → токен в `ALERT_TELEGRAM_BOT_TOKEN`.
2. Свой id — у @userinfobot → в `ALERT_TELEGRAM_CHAT_ID`.
3. Написать своему боту `/start` (иначе Telegram не даёт ему писать первым).

**Пульс — Healthchecks.io** (бесплатно)
1. Новая проверка: Period — 5 минут, Grace — 5 минут.
2. Адрес пинга → `ALERT_HEARTBEAT_URL`. Сторож шлёт `…/fail`, когда какая-то
   проверка в сбое: Healthchecks тоже сообщит — второй, независимый путь тревоги.
3. В Healthchecks → Integrations: почта (есть сразу) и Telegram.

**ntfy** (необязательно) — приложение-уведомления: `ALERT_NTFY_URL=https://ntfy.sh/<длинное-случайное-имя>`.
Имя темы — как пароль: кто его знает, читает сообщения.

**Почта через Resend** (необязательно): `ALERT_EMAIL_TO`, `ALERT_EMAIL_FROM` (на домене,
подтверждённом в Resend), `ALERT_RESEND_API_KEY`.

## Безопасность

- Сторож только **отправляет**: бот не читает входящие и не принимает команд —
  атаковать через мессенджер нечего.
- В сообщениях нет IP и других данных посетителей — только состояние сервера.
  Поэтому в карту персональных данных (docs/03 п.11) сторож не входит.
- Токены — только в `.env` (права 600). В журнал попадает имя канала и код ответа,
  не токен; значения проверяются по формату, адрес запроса из них не собрать.
- У сторожа нет доступа к Docker и к базе; весь `.env` он не видит — только свои
  переменные (`docker-compose.yml`). Файловая система — только для чтения.
- Утёк токен бота — @BotFather → `/revoke`, новый — в `.env`,
  `docker compose up -d watchdog`.

## Журнал вручную

```bash
docker compose logs -f watchdog     # что видит сторож
docker compose ps                   # состояние всех контейнеров
```
