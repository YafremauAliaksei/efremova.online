# 🔓 06 — Публичный репозиторий без утечки личного

Код открыт для проверки. Личного и секретного в репозитории нет ни байта:
стойкость системы зависит от ключей, а не от секретности устройства.

---

## 1. Разделение «как» и «что»

| Публичный репозиторий — КАК устроен сайт | Сервер — ЧТО на сайте |
|---|---|
| код страниц и логики | тексты «Обо мне», «Подход» |
| схема базы данных | фотографии |
| правила безопасности, конфиги nginx и Docker | реальные цены, отзывы |
| `.env.example` — имена ключей | `.env` — значения ключей |
| демо-заглушки в `prisma/seed.ts` | всё настоящее содержимое |

Весь контент сайта лежит в базе, а не в коде, и правится через админку.

---

## 2. Что никогда не попадает в репозиторий

```
❌ .env с настоящими значениями
❌ ключи: *.pem, *.key, service-account.json, id_rsa
❌ terraform.tfstate, terraform.tfvars
❌ дампы базы: *.sql вне prisma/migrations, *.dump, backups/
❌ реальные фото, тексты, цены и отзывы владельца
❌ IP-адрес сервера (он в переменных Terraform)
❌ настоящие email и телефоны — даже в комментариях и тестах
   (в тестах: example.com, +48 000 000 000)
```

---

## 3. Почему открытый код не делает сайт уязвимее

Схема базы, алгоритмы и логика проверки прав доступа не дают. Реальный риск
один — видны версии библиотек; он закрыт Dependabot и еженедельным сканом в CI.

---

## 4. Три линии защиты от утечки секрета

1. **`.gitignore`** — от невнимательности.
2. **Хук перед коммитом** — `scripts/check-staged-secrets.mjs` проверяет то, что
   уходит в коммит (`npm run hooks:install`). Обходить (`--no-verify`) нельзя.
   Исключения в нём узкие: первая версия считала безопасной любую строку
   со словом `example` и пропускала настоящий по виду ключ AWS.
3. **CI** — Gitleaks по всей истории, независимая вторая реализация;
   плюс GitHub Secret Scanning с Push protection.

---

## 5. Если секрет всё-таки попал в git

Новый коммит поверх не помогает: старый остаётся в истории, в кэше GitHub
и в зеркалах, которые боты снимают за секунды.

```
1. ОТОЗВАТЬ КЛЮЧ — немедленно, до любых правок в git.
2. Выпустить новый и положить в .env на сервере.
3. Почистить историю (git filter-repo) — это гигиена, а не защита.
```
