# efremova.online

Платформа частного психолога: публичный сайт + защищённый кабинет клиента
с расписанием, видеосвязью и платежами.

> **Начните отсюда:** [`PROJECT_LOG.md`](PROJECT_LOG.md) — что сделано, что дальше,
> что требуется от вас. Это главный файл проекта.

---

## 📦 Что это и в каком оно состоянии

**Это веб-приложение, а не программа для скачивания.** Здесь нет файла, который
можно скачать и запустить двойным щелчком: нет `.exe`, `.apk` и готовой сборки
в разделе Releases. Сайт «собирается» из исходного кода и работает на сервере,
а посетитель видит его в браузере.

Отсюда и способ посмотреть: не «скачать релиз», а **запустить у себя** — тремя
командами, см. «Быстрый старт» ниже.

**Состояние: в разработке, публично не запущено.**

| Часть | Состояние |
|---|---|
| Публичный сайт (главная, услуги, правовые документы) | 🟡 каркас работает, идёт оформление |
| Админка для правки текстов | ✅ работает |
| Личный кабинет, авторизация, запись на приём | ⬜ не начато |
| Платежи, видеосвязь | ⬜ не начато |

**Почему нет ни одного релиза.** Тег версии имеет смысл, когда есть куда
выкатывать: он отвечает на вопрос «какой код сейчас работает у людей». Прода
пока нет, отвечать не на что. Первый тег появится вместе с первым
развёртыванием.

## 👀 Как это посмотреть — три способа

**1. Просто почитать код.** Ничего устанавливать не нужно. С чего начинать —
карта репозитория ниже.

**2. Запустить у себя.** Нужны Node.js 22+, Docker и Git. Три команды из
«Быстрого старта» поднимут сайт на `http://localhost:3000` с демо-содержимым.
Внешние ключи не требуются: способы входа, для которых нет ключей, честно
показываются как недоступные.

**3. Поднять «как на сервере».** `npm run stack:up` соберёт Docker-образ и
запустит именно то, что поедет в прод: тот же Node, тот же пользователь,
файловая система только для чтения.

## ⚡ Быстрый старт

**Что должно быть установлено:** Node.js 22+, Docker, Git.
Проверка того, что уже есть:

```bash
node -v && docker -v && git --version
```

### Запуск с нуля — две команды

```bash
npm install
```

```bash
npm run setup
```

`setup` делает всё сам: создаёт `.env` со случайными локальными секретами,
поднимает PostgreSQL и Redis в Docker, создаёт таблицы, заливает
демо-содержимое и ставит git-хук проверки секретов.

Затем:

```bash
npm run dev
```

Сайт откроется на `http://localhost:3000`.

> **Внешние ключи не нужны.** Ни Google, ни Telegram, ни платежи.
> Сайт работает и честно показывает, что способы входа не подключены —
> это не заглушка, а результат реальной проверки
> ([как устроено](docs/08-auth-availability-and-privacy.md)).

### Полное окружение в Docker (как на сервере)

```bash
docker compose up -d
```

## 🕵️ Проверить безопасность самому

Репозиторий публичный **ради этого**: код, обрабатывающий данные о здоровье,
должен быть открыт для независимой проверки. Обоснование —
[`docs/06-public-repo-strategy.md`](docs/06-public-repo-strategy.md).

### Прогнать те же проверки, что и конвейер

```bash
npm run ci
```

Одиннадцать проверок, включая сканирование секретов (Gitleaks), уязвимостей
в образе (Trivy), конфигурации инфраструктуры (Checkov) и заголовков
безопасности на реально поднятом контейнере. В конце скрипт печатает, чего он
**не** покрывает — Lighthouse и полное сканирование ZAP идут только в pull request.

Отдельно заголовки на боевом образе:

```bash
npm run security:headers:local
```

### Что сделано нарочно и не является дырой

Чтобы не тратить ваше время на ложные следы:

| Что вы увидите | Что это на самом деле |
|---|---|
| `/.env`, `/wp-admin`, `/phpmyadmin` отвечают с задержкой в несколько секунд | ловушки: задержка случайная (2–5 с), она замедляет перебор, а обращение записывается. Приложение написано не на PHP, и файла `.env` в нём нет |
| `/api/internal/users` возвращает «данные пользователей» | ловушка: данные фальшивые, с метками-канарейками |
| Способы входа показаны как недоступные | так и есть: ключей нет, и это проверяется живой пробой |
| `style-src` в CSP содержит `unsafe-inline` | осознанный компромисс, обоснование в `src/lib/security/headers.ts` |
| `extract-zip` с открытой уязвимостью в зависимостях | патча не существует; риск принят со сроком и обоснованием в `scripts/check-audit.mjs` |

Устройство ловушек описано в [`docs/03-security-policy.md`](docs/03-security-policy.md).

### Нашли настоящую уязвимость

**Не открывайте публичный issue.** Порядок приватного сообщения и сроки ответа —
в [`SECURITY.md`](SECURITY.md). Коротко: GitHub → вкладка Security → Report
a vulnerability.

Особенно ценны находки в областях: обход авторизации, доступ к чужим данным,
утечка персональных данных в логи или в разметку, обход проверки подписи
платёжного webhook.

## 🔐 Правила, нарушение которых недопустимо

Полный список — в [`docs/03-security-policy.md`](docs/03-security-policy.md), п.9.

1. Файл `.env` и любые ключи **никогда** не попадают в git.
2. Данные клиентов хранятся только в ЕС.
3. Личный кабинет не кэшируется и не индексируется.
4. Статус платежа меняется только по webhook с проверенной подписью.
5. Каждый доступ к медицинским данным пишется в журнал аудита.
6. Прод-база на личном компьютере — никогда.
7. Бэкап без проверенного восстановления бэкапом не считается.
