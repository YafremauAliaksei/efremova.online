## ⚡ Быстрый старт

**Что должно быть установлено:** Node.js 22+, Docker, Git.
Проверка того, что уже есть:

```bash
node -v && docker -v && git --version
```

### Запуск с нуля — две команды

```bash
npm install
```

```bash
npm run setup
```

`setup` делает всё сам: создаёт `.env` со случайными локальными секретами,
поднимает PostgreSQL и Redis в Docker, создаёт таблицы, заливает
демо-содержимое и ставит git-хук проверки секретов.

Затем:

```bash
npm run dev
```

Сайт откроется на `http://localhost:3000`.

> **Внешние ключи не нужны.** Ни Google, ни Telegram, ни платежи.
> Сайт работает и честно показывает, что способы входа не подключены —
> это не заглушка, а результат реальной проверки
> ([как устроено](docs/08-auth-availability-and-privacy.md)).

### Полное окружение в Docker (как на сервере)

```bash
docker compose up -d
```

## 🧰 Полезные команды

| Команда | Что делает |
|---|---|
| `npm run setup` | Первичная настройка одной командой |
| `npm run dev` | Запуск в режиме разработки, с автообновлением |
| `npm run dev:db` | Поднять только базу и Redis |
| `npm run db:seed` | Залить демо-содержимое |
| `npm run verify` | Полная проверка: типы + линтер + формат + тесты |
| `npm run db:studio` | Визуальный просмотр базы данных в браузере |
| `npm run security:headers` | Проверка заголовков безопасности |
| `npm run lighthouse` | Проверка скорости и SEO |
| `docker compose logs -f app` | Смотреть логи приложения |

## 🔐 Правила, нарушение которых недопустимо

Полный список — в [`docs/03-security-policy.md`](docs/03-security-policy.md), п.9.

1. Файл `.env` и любые ключи **никогда** не попадают в git.
2. Данные клиентов хранятся только в ЕС.
3. Личный кабинет не кэшируется и не индексируется.
4. Статус платежа меняется только по webhook с проверенной подписью.
5. Каждый доступ к медицинским данным пишется в журнал аудита.
6. Прод-база на личном компьютере — никогда.
7. Бэкап без проверенного восстановления бэкапом не считается.
