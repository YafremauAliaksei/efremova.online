# efremova.online

Сайт-визитка частного психолога. Цели и список задач — [`PROJECT_LOG.md`](PROJECT_LOG.md),
устройство сайта — [`docs/13-site-architecture.md`](docs/13-site-architecture.md).

**Состояние: в разработке, публично не запущено.** Личный кабинет, запись и платежи
отложены и уедут на поддомен `cabinet.` на отдельном сервере.

## ⚡ Быстрый старт

Нужны Node.js 22+, Docker, Git. Внешние ключи не нужны.

```bash
npm install
```

```bash
npm run setup
```

```bash
npm run dev
```

`setup` создаёт `.env` со случайными локальными секретами, поднимает PostgreSQL
в Docker, применяет миграции, заливает демо-содержимое и ставит git-хук проверки
секретов. Сайт — на `http://localhost:3000`.

На машине с 6 ГБ ОЗУ сборка и dev-сервер идут с лимитом кучи 2 ГБ
(`scripts/run-next.mjs`, переменная `NEXT_MEMORY_LIMIT_MB`).

## 🧰 Команды

| Команда | Что делает |
|---|---|
| `npm run verify` | типы + линтер + формат + тесты |
| `npm run ci` | 11 проверок, 7 из 8 ворот GitHub; нужен Docker |
| `npm run ci:quick` | быстрая часть без Docker |
| `npm run admin:link` | одноразовая ссылка входа в админку (15 минут) |
| `npm run stack:up` | приложение в Docker «как на сервере» |
| `npm run dev:db` | только база данных |
| `npm run db:seed` | демо-содержимое |
| `npm run db:studio` | просмотр базы в браузере |
| `npm run security:headers:local` | заголовки безопасности на боевом образе |
| `npm run security:audit` | уязвимости в production-зависимостях с принятыми рисками |

## 🕵️ Проверить безопасность самому

Репозиторий открыт для независимой проверки. Те же проверки, что в конвейере:

```bash
npm run ci
```

Lighthouse и полное сканирование ZAP идут только в pull request — скрипт
печатает это в конце.

### Что сделано нарочно и не является дырой

| Что вы увидите | Что это на самом деле |
|---|---|
| `/.env`, `/wp-admin`, `/phpmyadmin` отвечают с задержкой | ловушки: первое обращение с адреса за минуту ждёт 2–5 с и записывается, повторные отвечают сразу. Файла `.env` в приложении нет |
| `/api/internal/users` возвращает «данные пользователей» | ловушка: данные фальшивые, с метками-канарейками |
| В ответах нет ни одного внешнего домена | так задумано: `default-src 'self'`, `frame-src 'none'`, `connect-src 'self'` — `src/lib/security/headers.ts` |
| `style-src` в CSP содержит `unsafe-inline` | осознанный компромисс, обоснование в `src/lib/security/headers.ts` |
| `extract-zip` с открытой уязвимостью | патча не существует; риск принят со сроком в `scripts/check-audit.mjs` |

### Нашли настоящую уязвимость

Не открывайте публичный issue — порядок в [`SECURITY.md`](SECURITY.md):
GitHub → Security → Report a vulnerability.
